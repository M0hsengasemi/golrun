# گل‌ران ۶.۲ — بسته نصب موبایل و انتشار خودکار

این بسته نسخه بازطراحی‌شده گل‌ران را همراه با فایل‌های PWA، پیکربندی Capacitor و گردش‌کارهای GitHub Actions برای انتشار وب و ساخت APK آزمایشی ارائه می‌کند.

## نصب ساده بدون APK (PWA)
1. محتویات ZIP را در مخزن GitHub خود بارگذاری کنید؛ خود ZIP را در ریشه مخزن نگذارید.
2. در GitHub، `Settings → Pages` را باز کنید و Source را روی `GitHub Actions` بگذارید.
3. در `Actions` اجرای `Deploy GolRun to GitHub Pages` را اجرا کنید و تا سبز شدن نتیجه صبر کنید.
4. آدرس سایت منتشرشده را با Chrome گوشی باز کنید.
5. از منوی سه‌نقطه Chrome گزینه «نصب برنامه» یا «افزودن به صفحه اصلی» را انتخاب کنید. دکمه «نصب برنامه» نیز در برنامه، در مرورگرهای پشتیبانی‌شده ظاهر می‌شود.

## ساخت APK اندروید
1. پس از ثبت محتویات بسته در شاخه `main`، وارد زبانه `Actions` شوید.
2. گردش‌کار `Build GolRun Android APK` را باز کنید و `Run workflow` را بزنید؛ یا اجرای خودکار پس از Commit را انتخاب کنید.
3. پس از سبز شدن اجرا، پایین صفحه در بخش `Artifacts` فایل `golrun-android-debug-apk` را دانلود کنید.
4. ZIP مربوط به Artifact را در گوشی استخراج کنید و `app-debug.apk` را نصب کنید. اجازه نصب از منبع مورد استفاده ممکن است لازم باشد.

## وضعیت واقعی و محدودیت‌ها
- APK در این ZIP از پیش ساخته نشده است؛ GitHub Actions باید آن را بسازد. این محیط به حساب GitHub شما متصل نیست و نمی‌تواند اجرای workflow را به جای شما انجام دهد.
- APK خروجی debug برای نصب و آزمایش است، نه نسخه امضاشده نهایی برای انتشار در فروشگاه.
- آگهی‌ها و علاقه‌مندی‌ها در نسخه فعلی عمدتاً روی دستگاه/مرورگر ذخیره می‌شوند. برای چندکاربره واقعی، سرور مرکزی، پایگاه داده امن، احراز هویت، آپلود تصاویر، گزارش تخلف، پیام‌رسانی سراسری، کنترل ضدتقلب و پنل مدیریتی آنلاین باید بک‌اند جداگانه پیاده‌سازی و آزمایش شود.
- خدمات ویژه و تعرفه در رابط برنامه به معنی دریافت پول واقعی نیست؛ اتصال پرداخت باید از طریق ارائه‌دهنده مجاز و بک‌اند امن انجام شود.
- قبل از انتشار عمومی، سیاست حریم خصوصی، شرایط استفاده، روند حذف آگهی و سازوکار گزارش تخلف را تکمیل کنید.

## افزوده‌های نسخه ۶.۳: فهرست سراسری و زیرساخت ابری

- فیلتر نمایشگاه‌ها بر اساس استان و شهر حفظ شده و قالب CSV اطلاعات منبع، پیوند منبع، مرجع صدور پروانه و تاریخ بررسی را می‌پذیرد.
- برای جلوگیری از معرفی اشتباه، واردکردن CSV یا ثبت توسط کاربران به‌تنهایی نمایشگاه را «مجاز/تأییدشده» نمی‌کند؛ تأیید باید پس از تطبیق با مرجع رسمی انجام شود.
- `data/dealerships-template.csv` قالب آماده برای گردآوری داده‌های رسمی است.
- `supabase/schema.sql` اسکیمای پایه برای آگهی‌های آنلاین مشترک، نمایشگاه‌ها، حساب‌ها و رویدادهای بررسی است؛ سیاست‌های RLS نمایش عمومی آگهی‌های تأییدشده و نمایشگاه‌های تأییدشده را محدود می‌کنند.
- `supabase/functions/ai-moderate/index.ts` نمونهٔ سروری بررسی اولیه آگهی است؛ در وضعیت فعلی قواعد اولیه را بررسی می‌کند و **مدل هوش مصنوعی واقعی نیست**.

### محدودیت مهم — چه چیزهایی هنوز فعال نشده‌اند

این بسته به‌تنهایی به پایگاه داده آنلاین متصل نیست و فهرست رسمی کامل همه نمایشگاه‌داران کشور را در خود ندارد. برای سرویس واقعی باید یک پروژه Supabase (یا سرور معادل)، احراز هویت، بارگذاری امن عکس‌ها، APIهای انتشار/مدیریت، کنترل ضداسپم و اتصال فرانت‌اند به API مستقر شود. همچنین باید فهرست نمایشگاه‌ها از اتحادیه‌ها/مرجع رسمی صدور پروانه دریافت و شماره تماس، نشانی و اعتبار پروانه بررسی شود. **هیچ فهرست سراسری حدسی یا شماره تلفن ساختگی اضافه نشده است.**

برای فعال‌شدن هوش مصنوعی ابری باید ارائه‌دهنده مدل، کلید محرمانه سمت سرور، بودجه/محدودیت مصرف و ارزیابی خطا تنظیم شود؛ کلید محرمانه را در فایل HTML یا اپ موبایل قرار ندهید. تا آن زمان، راهنمای محلی برنامه فقط پیشنهاد کمکی می‌دهد و نباید تصمیم نهایی تأیید آگهی را خودکار بگیرد.
